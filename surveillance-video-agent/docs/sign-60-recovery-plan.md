# 举牌 60 条恢复计划

> 状态：未采纳。用户选择先放宽到手机拍摄并估算三平台潜在样本量，不启用 Visual Scout。

日期：2026-08-27  
目标：获得 60 条经外部人工确认可用的固定监控举牌/横幅视频。

## 1. 为什么现有路径无法完成

当前文本路径已经执行：三平台多语言查询、地点切片、动作短语锁定、来源分 `>=6`、Qwen embedding `>0.44`、两轮混合 demand Pilot 和一轮 Sign Focus Pilot。

人工结果：举牌共 8 条标签，任务可用为 0。Sign Focus 的公开元数据甚至出现“banner/sit-in/protest”，但实际画面仍被判定为来源错误或没有举牌。问题是元数据与画面不一致，不是候选池上限或阈值设置。

因此不能通过继续降阈值、复制查询包或扩大文本 Top-K 获得 60 条可用数据。

## 2. 唯一可规模化的修订

保持最终下载流水线不变，在上游新增独立组件：`Visual Scout`。

```text
三平台/网页发现 DB（可大）
        ↓
来源与资源元数据硬门
        ↓
缩略图侦察（低成本）
        ↓
低清临时预览 + 均匀抽帧（仅 Top 候选）
        ↓
Qwen3-VL：固定摄像头？人物实际举牌/展开横幅？
        ↓
scout_recommended（不是 accepted）
        ↓
现有 v2 Frontier → 串行正式下载 → 技术验证 → Manifest
        ↓
外部人工标注，累计 usable_sign_count
```

Visual Scout 是发现系统，不拥有 v2 状态机，也不能写 `accepted`。临时缩略图/低清预览不进入 `Candidate_Downloads`，完成推理后清理；数据库只保存候选键、模型/提示版本、帧时间点、结构化判定和理由摘要。

## 3. 目标与容量

新建独立 Campaign：`sign_action_v1`。

- 人工可用目标：60。
- 单轮 Scout 释放：20。
- 正式下载候选预算：最多 300；不等于必须下载 300。
- 技术字节预算：继续 30GB。
- 上传者上限：全 Campaign 5 条。
- 来源分、资源限制和精确去重保持不变。
- 最终下载继续全局串行。

当前 23 个已发布媒体平均约 23 MiB。即使正式下载 300 个同等体量候选，估算约 6.8GB，低于 30GB；真正限制是检索精度，不是存储。

## 4. 两级视觉侦察

### 4.1 缩略图级

对搜索发现候选读取平台公开缩略图，结构化判断：

1. 是否明显为监控/门铃/固定高位视角；
2. 是否可见人物手持牌、标语板、横幅或正在展开/悬挂牌面；
3. 是否明显为新闻主播、影视、游戏、教程、设备广告。

只有来源与举牌任一项不是明确否的候选进入低清预览。

### 4.2 低清预览级

只对缩略图 Top 候选获取受限低清临时预览，均匀取 6–12 帧。Qwen3-VL 必须输出固定 JSON：

```json
{
  "fixed_surveillance": true,
  "visible_sign_or_banner": true,
  "visible_in_frame_count": 3,
  "news_or_fiction_packaging": false,
  "confidence": 0.0,
  "reason_codes": []
}
```

进入 `scout_recommended` 的最低条件：

- `fixed_surveillance=true`；
- `visible_sign_or_banner=true`；
- 至少 2 帧可见；
- `confidence>=0.75`；
- 不命中既有硬排除。

## 5. 收敛与停止

### Scout Pilot

先正式下载 20 个 `scout_recommended`，交给外部人工标注。

- `>=10/20` 举牌可用：Scout 方向通过，继续增量消费。
- `6–9/20` 可用：只允许调整 Scout 提示/帧策略一次，再跑 20 条。
- `<=5/20` 可用：停止，不能通过降低置信度扩量。

### 60 条收敛

满足以下全部条件时停止：

1. 外部人工累计 `usable_sign_count=60`；
2. 最近 40 个正式下载候选任务可用率 `>=40%`；
3. 来源正确率 `>60%`；
4. 技术成功率 `>90%`；
5. Manifest 完整率 100%；
6. 无 SHA-256 重复；
7. 每上传者累计不超过 5 条。

按 50% 人工可用率估算，需要约 120 个正式候选；按 40% 估算约 150 个。300 是失败保护上限，不是下载计划。

## 6. 需要确认的架构边界

本方案需要解除一条此前冻结的限制：允许在 **最终下载流水线之外** 使用缩略图、低清临时预览、均匀抽帧和 VLM 做候选侦察。

不解除这条限制时，当前证据无法支持“60 条真实可用举牌监控视频”的承诺。
